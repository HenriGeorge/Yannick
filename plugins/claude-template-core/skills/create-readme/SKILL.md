# Create README

## Task

1. Review the entire project and workspace
2. Create a comprehensive, well-structured README.md

## Guidelines

- Do not overuse emojis — keep concise and to the point
- Do not include LICENSE, CONTRIBUTING, CHANGELOG sections (those have dedicated files)
- Use GitHub Flavored Markdown with admonition syntax where appropriate
- If you find a logo or icon for the project, use it in the header

## Structure

1. **Title + one-line description**
2. **Quick start** (< 5 steps to running)
3. **Key features** (bullet list, not walls of text)
4. **Architecture overview** (if complex — keep brief)
5. **Prerequisites** (runtime versions, required services)
6. **Installation**
7. **Usage examples** (show the most common operations)
8. **Configuration** (environment variables, config files)
9. **API reference** (link to docs if extensive)
10. **Development** (how to contribute, run tests)
